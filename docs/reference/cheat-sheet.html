React 19 cheat sheet

Every signature, rule and type you look up more than once, on one page.

CurrentReact 19.2+

Lookup, not reading. Signatures use ? for optional parameters. Fragments shown as text are deliberately incomplete — they are meant to be pattern-matched, not pasted.

Hooks#

All from react except where noted.

HookSignatureUse when
useStateconst [s, setS] = useState(init)A value changes and the UI must follow.
useReducerconst [s, dispatch] = useReducer(reducer, initialArg, init?)Several fields move together, or transitions are a state machine.
useContextconst v = useContext(Ctx)Reading a value provided higher in the tree.
useRefconst r = useRef(init)A value that must survive renders without causing one.
useImperativeHandleuseImperativeHandle(ref, createHandle, deps?)A parent needs methods, not the raw DOM node.
useEffectuseEffect(setup, deps?)Synchronizing with something outside React.
useLayoutEffectuseLayoutEffect(setup, deps?)You must measure or reposition before paint.
useInsertionEffectuseInsertionEffect(setup, deps?)You are writing a CSS-in-JS library. Otherwise never.
useEffectEventconst onEvent = useEffectEvent(fn)An Effect reads a value it must not react to. (19.2)
useMemoconst v = useMemo(calc, deps)A calculation is measurably slow.
useCallbackconst f = useCallback(fn, deps)A function identity feeds a memo'd child or a dep array.
useTransitionconst [isPending, startTransition] = useTransition()An update may block typing, and you want a spinner.
useDeferredValueconst d = useDeferredValue(value, initialValue?)You own the value but not the update. (initialValue 19.0)
useIdconst id = useId()Wiring <label htmlFor> / aria-* across SSR.
useSyncExternalStoreuseSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?)Subscribing to a store outside React.
useDebugValueuseDebugValue(value, format?)Labelling a library custom hook in DevTools.
useActionStateconst [state, formAction, isPending] = useActionState(action, initialState, permalink?)A submit needs result + pending + error state. (19.0)
useFormStatusconst { pending, data, method, action } = useFormStatus()A child of a <form> needs its pending state. react-dom. (19.0)
useOptimisticconst [opt, addOptimistic] = useOptimistic(state, updateFn?)Showing a result before the server confirms. (19.0)
useconst v = use(resource)Reading a promise or context. Not a hook — may be conditional. (19.0)

Rules of Hooks, in one line each:

Top level only — never in a condition, loop, nested function or try/catch.
React functions only — components or custom hooks, nothing else.
Same order every render — that ordering is how React identifies each hook.
`use` is exempt from all three.

Conditional rendering#

if (!user) return <SignIn />;              // early return — clearest
{isAdmin ? <AdminBar /> : <UserBar />}     // either/or
{error && <ErrorText message={error} />}   // render or nothing
{items.length > 0 && <List items={items}/>}// guard a list

Warning

The 0 trap: {count && <Badge />} renders the number 0 when count is 0, because 0 is falsy but is still a valid React child. Write {count > 0 && <Badge />} or {count ? <Badge /> : null}.

Same trap with '' (renders nothing, harmless) and NaN (renders NaN).

Lists and keys#

{users.map(user => <UserRow key={user.id} user={user} />)}
{pairs.map(p => <Fragment key={p.id}><dt>{p.term}</dt><dd>{p.def}</dd></Fragment>)}
RuleWhy
key goes on the outermost element inside map.React reads it from the array element.
Keys must be stable across renders.Math.random() remounts everything, every time.
Keys must be unique among siblings only.Not globally.
Prefer a data ID.It survives sorting, filtering and insertion.
Index keys are acceptable only for a static, never-reordered list.Otherwise state attaches to the wrong row.
key is not a prop.props.key is undefined; pass an id prop too if you need it.
A keyed fragment needs <Fragment key>.<> accepts no props.

Forms and Actions#

<form action={submitOrder}>            // function → runs as an Action, POST, resets uncontrolled fields
<form action="/search">                // string  → plain HTML behavior
<button formAction={saveDraft}>        // overrides the form's action
APIShapeGives you
useActionStateconst [state, formAction, isPending] = useActionState(action, initialState, permalink?)The action's return value, a wrapped action for <form action>, and pending.
useFormStatusconst { pending, data, method, action } = useFormStatus()Parent form status. Must be in a child of the form.
useOptimisticconst [opt, addOptimistic] = useOptimistic(state, updateFn?)A provisional value; addOptimistic must run inside an Action or startTransition.

The action function receives one argument, the FormData. With useActionState it receives (previousState, formData).

Refs#

const inputRef = useRef(null);          // DOM node
<input ref={inputRef} />
inputRef.current?.focus();              // read in an event or Effect, never during render

const timerRef = useRef(0);             // any mutable value
timerRef.current = window.setTimeout(tick, 1000);

Callback refs, with cleanup (19.0 — returning a cleanup function is new):

<div ref={(node) => {
  const observer = new ResizeObserver(onResize);
  if (node) observer.observe(node);
  return () => observer.disconnect();
}} />

useImperativeHandle(ref, createHandle, deps?) narrows what a parent can touch:

function TextField({ ref }) {
  const inputRef = useRef(null);
  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current?.focus(),
  }), []);
  return <input ref={inputRef} />;
}

Context#

const ThemeContext = createContext('light');     // default used only with no provider above

<ThemeContext value={theme}>{children}</ThemeContext>   // 19.0: the context renders as the provider
const theme = useContext(ThemeContext);                 // unconditional
const theme = use(ThemeContext);                        // may be conditional

Every consumer re-renders when value changes by Object.is. Memoize an object value, split one context into two, or move to an external store when that becomes a problem.

Suspense and use()#

  <Profile />
</Suspense>

const user = use(userPromise);   // suspends until it settles; throws if it rejects
Suspense reacts toSuspense ignores
lazy() component codefetch inside useEffect

Streaming SSR HTML

The promise passed to use() must be cached — creating it during render makes a new one every attempt and suspends forever. Create it in a Server Component, a cache, or a data library.

Reveals are batched at roughly one every 300ms so boundaries do not pop in one by one. Pair use() with an Error Boundary: a rejected promise throws.

Error boundaries#

Still the one place a class component is required. React has no hook equivalent.

class ErrorBoundary extends Component {
  state = { error: null };
  static getDerivedStateFromError(error) { return { error }; }   // render the fallback
  componentDidCatch(error, info) { report(error, info.componentStack); }  // log it
  render() {
    return this.state.error ? this.props.fallback : this.props.children;
  }
}

Boundaries do not catch: errors in event handlers, in setTimeout, during server rendering, or thrown by the boundary itself.

Root-level options (19.0), passed to createRoot / hydrateRoot:

OptionFires when
onCaughtErrorAn Error Boundary caught the error.
onUncaughtErrorNothing caught it and the root is unmounting.
onRecoverableErrorReact recovered on its own, e.g. a hydration mismatch.

TypeScript#

tsx
import { useState, useRef, useCallback } from 'react';
import type { ReactNode, ChangeEvent, MouseEvent, Ref } from 'react';

type FieldProps = {
  label: string;
  defaultValue?: string;
  children?: ReactNode;
  ref?: Ref<HTMLInputElement>;
  onChange?: (event: ChangeEvent<HTMLInputElement>) => void;
};

export function Field({ label, defaultValue = '', children, ref, onChange }: FieldProps) {
  const [value, setValue] = useState<string>(defaultValue);
  const resetRef = useRef<HTMLButtonElement | null>(null);

  const handleReset = useCallback((event: MouseEvent<HTMLButtonElement>) => {
    event.preventDefault();
    setValue('');
  }, []);

  return (
    <label>
      {label}
      <input ref={ref} value={value} onChange={(e) => { setValue(e.target.value); onChange?.(e); }} />
      <button ref={resetRef} onClick={handleReset}>Reset</button>
      {children}
    </label>
  );
}

Legacy

Removed in 19.0. Nothing here exists any more: propTypes · defaultProps on function components (use default parameters) · legacy context (contextTypes / getChildContext) · string refs · module pattern factories · React.createFactory · ReactDOM.render (use createRoot) · ReactDOM.hydrate (use hydrateRoot) · unmountComponentAtNode (use root.unmount()) · ReactDOM.findDOMNode (use refs) · react-dom/test-utils (act now comes from react) · react-test-renderer/shallow (use the react-shallow-renderer package) · unstable_flushControlled · unstable_createEventHandle · unstable_renderSubtreeIntoContainer · unstable_runWithPriority · UMD builds (use an ESM CDN such as esm.sh).

Deprecated

Deprecated in 19.0 — these still run, but do not write new code this way: forwardRef (ref is a prop) · rendering a context through its .Provider property (render the context itself) · element.ref (read element.props.ref) · react-test-renderer (use @testing-library/react).

Common mistakes#

  • {count && <Badge />} when count is 0. Compare explicitly.
  • key={index} on a list that reorders. State follows the key, not the data.
  • useFormStatus imported from react, or called in the component that renders the <form>.
  • value={undefined} on an input, flipping it from controlled to uncontrolled.
  • Reading ref.current during render.
  • Creating the promise for use() inside the render that consumes it.
  • useEffect for derived state that could be computed during render.
  • Memoizing everything before profiling anything.
  • onClick={handleClick()} instead of onClick={handleClick}.
