Learning path

An ordered route through this site, from first component to production React 19.

Current

Read in this order and each page assumes only what came before it. Skipping ahead is fine once you know what you are looking for, but the ordering is not arbitrary: most confusion about hooks traces back to a gap in Stage 1, and most confusion about performance traces back to a gap in Stage 2.

Five stages, roughly a week each if React is new to you.

Stage 0 — Orientation#

  • Introduction to React — what React is, the UI-as-a-function-of-state model, and how reconciliation works. Start here even if you have used React before; the React 19 framing has changed.
  • Installation — a running dev server on React 19.2.8, with the Hooks linter and DevTools installed. Do not skip the linter.
  • Your first component — markup, props, state, an event handler, a list. After this you can build a small screen.
  • Thinking in React — the five-step process from a design to a component tree. This is the page you will re-read most often.

Stage 1 — Foundations#

Everything here is mandatory. These nine pages are the vocabulary the rest of the site uses without explanation.

  • JSX — what the markup compiles to, and the rules (one root, className, braces for expressions).
  • Components — the unit of composition, and where to draw boundaries.
  • Props — data down, including children and prop spreading. After this you can build reusable components.
  • State — what belongs in state, why it is a snapshot per render, and why you never mutate it.
  • Rendering — trigger, render, commit. Read this before you form any opinion about React performance.
  • Conditional rendering — &&, ternaries, and the falsy-value trap that renders a stray 0.
  • Lists and keys — why key exists and how a bad key corrupts component state.
  • Events — handlers, the synthetic event, and why you pass a function rather than call one.
  • StrictMode — why development double-invokes your components, and why that is a feature.

Then the two hook pages that everything else builds on:

  • Rules of Hooks — top level only, same order every render. Understand the reason, not only the rule.
  • useState — the full API: updater functions, lazy initializers, and state as a per-render snapshot.

Stage 2 — State and Effects#

This is where most people get stuck, and where the biggest wins are. The theme: most things are not state, and most synchronization is not an Effect.

  • useReducer — for state whose transitions are worth naming, and where several values change together.
  • useRef — a value that survives renders without causing one. The escape hatch from the render cycle.
  • Refs and the DOM — reading and imperatively controlling DOM nodes, with ref as an ordinary prop in React 19.
  • useEffect — synchronizing with systems outside React. Read the "when not to use it" section twice.
  • useEffectEvent — reading the latest props inside an Effect without re-running it. New in 19.2, and it removes most dependency-array pain.
  • useLayoutEffect — measuring the DOM before the browser paints, and why it is a last resort.
  • useImperativeHandle — exposing a narrow imperative API from a component. Rare, and that is correct.
  • useId — stable unique ids for accessible form markup, safe under server rendering.
  • useDebugValue — labeling custom hooks in DevTools.
  • Custom hooks — extracting stateful logic. After this, your components stop growing.

Then how state travels between components:

  • Lifting state up — the lowest-common-ancestor rule, worked properly.
  • useContext — reading context, and the re-render behavior that surprises people.
  • Context — when context beats prop drilling and when it becomes a performance problem.
  • Reducers and context — the pattern that carries most apps to a surprising size without a library.
  • External stores — Zustand, Redux, or your own, and why they exist.
  • useSyncExternalStore — the correct way to subscribe to anything outside React, tear-free under concurrent rendering.
  • Choosing an approach — a decision table for local state, context, and stores. Read it before adding a dependency.

And the composition patterns that keep the tree manageable:

  • Composition — children, slots, and why you rarely need inheritance or a render prop.
  • Controlled inputs — value down, change up, and when uncontrolled is the better answer.
  • Forms and Actions — React 19 form Actions, which replace most hand-rolled submit handlers.
  • useActionState — pending state, errors, and the returned result of an Action, in one hook.
  • useFormStatus — a submit button that knows the parent form is pending, without prop drilling.
  • useOptimistic — showing the expected result before the server confirms it.
  • Error boundaries — the one place a class component is still required, plus the React 19 root error callbacks.
  • Portals — rendering into a different DOM node for modals and tooltips, without leaving the React tree.
  • Document metadata — <title>, <meta> and stylesheets rendered from components and hoisted to <head>. New in 19.0.

Stage 3 — Data#

You now know enough to fetch things without creating a race condition.

  • Data fetching overview — the four strategies and how to choose between them.
  • Fetching in Effects — how to do it correctly (cleanup, ignore flags, race conditions) and why it is the weakest option.
  • use — reading a promise or context during render, callable conditionally. New in 19.0 and unlike every other hook.
  • use with promises — suspending on data, and where the promise must come from.
  • Suspense — declarative loading states, boundaries, and what actually triggers one.
  • Caching — why a promise created during render is a bug, and what caches it correctly.
  • Data libraries — TanStack Query, RTK Query, and framework loaders. After this you can pick one on purpose.

Stage 4 — Performance and Server React#

Do not start here. Performance work without Stage 1 produces memoization that costs more than it saves.

  • Performance overview — measure first; the common causes of slow React apps, in order of frequency.
  • Profiling — the DevTools Profiler and the React 19.2 Performance Tracks in Chrome. Learn to read a flame graph before changing code.
  • React Compiler — v1.0 memoizes for you. Read this before the memoization page, because it changes the advice.
  • useMemo — caching an expensive computation, and how rarely one is expensive.
  • useCallback — a stable function identity, and the only situations where that matters.
  • Memoization — memo, useMemo, useCallback together, with the cost of each.
  • useTransition — marking updates as non-urgent so typing stays responsive.
  • useDeferredValue — deferring an expensive subtree, with the initialValue option added in 19.0.
  • Code splitting — lazy and Suspense, and where the split points belong.
  • Activity — <Activity /> keeps a hidden subtree's state and DOM alive. New in 19.2, and it replaces several hacks.
  • Lists and virtualization — when 10,000 rows need a windowing library.

Then React on the server:

  • Server React overview — the map: SSR, streaming, static generation, and Server Components are four different things.
  • Server Components — components that never ship to the browser. Stable in 19.0.
  • Directives — what "use client" and "use server" actually mark, and where the boundary falls.
  • Server Functions — calling the server from a client component, and how Actions build on this.
  • SSR and hydration — hydrateRoot, hydration mismatches, and how to debug one.
  • Streaming — sending HTML progressively, with Suspense boundaries as the flush points.
  • Static generation — prerender, and the partial pre-rendering postponed state added in 19.2.

Stage 5 — Production#

  • TypeScript setup — tsconfig, @types/react 19, and the version-matching rule.
  • Typing props — the props type, discriminated unions, and when to stop being clever.
  • Typing children — ReactNode versus ReactElement, and why children is no longer implicit in React 19.
  • Typing hooks — useState generics, ref types, and typing a reducer.
  • Typing events — the event types you actually need and where to find the rest.
  • Generic components — a typed <List> that infers its item type.
  • Semantics — the right element beats any ARIA attribute. The cheapest accessibility win there is.
  • Focus management — moving focus on route changes and in dialogs, with refs.
  • Announcements — live regions for content that changes without a page load.
  • Forms accessibility — labels, error association, and validation messaging.
  • Testing setup — Vitest or Jest with the jsdom environment, configured for React 19.
  • Testing Library — queries in priority order, and testing behavior rather than implementation.
  • act and async — act now imports from react, plus how to wait for async updates without flakiness.
  • User events — simulating real interaction rather than firing synthetic events.
  • Routing — React Router and Next.js App Router, and how each handles data loading.
  • Styling — CSS modules, utility CSS, and CSS-in-JS under Server Components.
  • Forms — React Hook Form and friends, and when React 19 Actions make them unnecessary.
  • Data libraries — choosing a client cache and how it interacts with Suspense.
  • Build tooling — Vite configuration, environment variables, and bundle analysis.
  • Redux — Redux Toolkit and RTK Query, with an honest account of when to use them.
  • Troubleshooting — the errors you will hit, and what each one actually means.

Common mistakes#

Mistakes about learning React, rather than about writing it.

  • Learning class components first. They still work, and error boundaries still require one, but every current API, example, and hiring conversation assumes function components. Start with hooks and meet classes in Legacy codebases.
  • Reaching for Redux on day two. Most apps never need a global store. Work through Lifting state up and Reducers and context first, then read Choosing an approach and decide with evidence.
  • Skipping the Rules of Hooks because the code appears to work. It works until a conditional early return changes the hook order. Install eslint-plugin-react-hooks and read Rules of Hooks properly.
  • Treating useEffect as the way to do anything after a render. Most Effects in a beginner codebase should be derived values, event handlers, or nothing at all. useEffect says when not to use it.
  • Memoizing before profiling. Wrapping every value in useMemo adds cost and hides the real problem. Read Performance overview and let the React Compiler do most of it.
  • Following React 18 tutorials without checking. A large fraction of published React material predates 19.0 and teaches removed API. Removed APIs is the filter.
  • Turning off StrictMode to silence a double-render warning, rather than fixing the impure render it found. See StrictMode.
  • Learning Server Components before client React. They are a deployment and data-flow model layered on top of everything in Stages 1 to 3. Out of order, they are incomprehensible.
