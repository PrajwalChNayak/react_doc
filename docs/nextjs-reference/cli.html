CLI reference

Every next command and flag in Next.js 16.3, plus create-next-app and the codemod CLI.

NNext.jsCurrentNext.js 16.3+Targets Next.js 16.3

Flags verified against the bundled 06-cli docs and the next binary in next@16.3.5. Run any command through your package manager: npx next …, pnpm next …. With npm run, put -- before flags so npm forwards them: npm run dev -- --port 4000.

next commands#

CommandPurposeSince
next devDevelopment server with Fast Refresh, error overlay and DevTools.
next buildProduction build. Prints each route as static (○) or dynamic (ƒ).
next startServes a production build. Run next build first.
next infoPrints OS, binaries, package versions and config for bug reports.
next typegenGenerates route types (PageProps, LayoutProps, RouteContext, next/root-params) and next-env.d.ts without building.15.5
next upgradeUpgrades Next.js in the current project.16.1
next experimental-analyzeTurbopack bundle analyzer. Produces no build.16.1
next telemetryEnables or disables anonymous telemetry.
next -v, next -hVersion, help.

next lint was removed in 16.0. Run eslint . (or Biome) directly; the next-lint-to-eslint-cli codemod rewrites the script.

next dev#

FlagMeaning
[directory]Project directory. Defaults to the current one.
-p, --port <port>Port. Default 3000, or PORT. PORT cannot come from .env.
-H, --hostname <hostname>Hostname. Default 0.0.0.0.
--webpackUse webpack instead of Turbopack, the default since 16.0.
--turbopack, --turboForce Turbopack. Redundant since 16.0.
--inspect [[host:]port]Attach the Node.js inspector to server code (16.1).
--experimental-httpsServe over HTTPS with a self-signed mkcert certificate.
--experimental-https-key <path>, --experimental-https-cert <path>, --experimental-https-ca <path>Use your own certificate files.
--experimental-upload-trace <traceUrl>Report part of the debug trace to a URL.
--experimental-cpu-profWrite V8 CPU profiles to .next-profiles/ on exit.

Since 16.0, next dev writes to .next/dev, so it can run while next build runs, and a lockfile stops a second next dev on the same project. In 16.3 it also maintains a version-matched block in AGENTS.md pointing coding agents at node_modules/next/dist/docs/.

next build#

FlagMeaning
[directory]Project directory.
--webpackBuild with webpack. Required if you keep a custom webpack config.
--turbopack, --turboForce Turbopack. With a webpack config present, builds with Turbopack and ignores that config.
-d, --debugVerbose output, including rewrites, redirects and headers.
--profileReact production profiling.
--no-manglingDisable name mangling. Debugging only.
--experimental-app-onlyBuild only App Router routes.
--experimental-build-mode [mode]compile or generate.
--debug-prerenderUnminified server code, server source maps, and continue past the first prerender error. Never deploy the result.
--debug-build-paths=<patterns>Build only matching route files. Comma-separated, globs allowed, ! excludes.
--experimental-cpu-profCPU profiles to .next-profiles/.
bash
next build --debug-build-paths="app/blog/**/page.tsx,!app/admin/**"

Since 16.0 the build no longer runs a linter and no longer prints size or First Load JS. Since 16.3 it reads and writes the Turbopack filesystem cache in .next/cache. Type checking runs the project's tsc CLI, so TypeScript 7 works.

FlagMeaning

next typegen#

FlagMeaning
[directory]Project directory, for example ./apps/web.

Writes to .next/types (or .next/dev/types) and creates next-env.d.ts. It loads next.config in the production build phase, so the config's environment variables must be available. Use it wherever you type-check without building:

bash
next typegen && tsc --noEmit

Node.js options#

Pass Node.js flags through NODE_OPTIONS:

bash
NODE_OPTIONS='--throw-deprecation' next build

For debugging, prefer next dev --inspect and next start --inspect. For other commands, the binary tells you to use NODE_OPTIONS='--inspect' instead.

@next/codemod#

bash
npx @next/codemod@canary upgrade latest

upgrade [revision] accepts patch, minor (the default), major, a dist tag such as latest or canary, or a version. It takes --verbose and -y, --yes; --yes is implied when stdin is not a TTY. Individual transforms run as npx @next/codemod <transform> <path> with --dry and --print.

TransformVersionDoes
cache-components-instant-false16.3Adds export const instant = false to pages, layouts and defaults.
remove-partial-prefetch16.3Removes export const prefetch = 'partial' after enabling partialPrefetching.
middleware-to-proxy16.0Renames the file, export and config flags.
remove-unstable-prefix16.0Drops unstable_ from stabilized imports.
remove-experimental-ppr16.0Removes the experimental_ppr segment export.
next-lint-to-eslint-cli16.0Replaces next lint with the ESLint CLI.
next-async-request-api15.0Awaits params, searchParams, cookies(), headers(), draftMode(). Not run by upgrade.

Pass ./src/app to the 16.3 transforms in a src/ project; a wrong path reports 0 ok instead of failing. See Next.js 15 to 16.

Common mistakes#

  • npm run dev --port 4000. npm swallows the flag. Use npm run dev -- --port 4000.
  • Keeping --turbopack in build scripts while a plugin adds a webpack config. The flag makes Turbopack ignore that config silently.
  • Running tsc --noEmit in CI without next typegen. PageProps and friends do not exist yet, so every page fails to type-check.
  • Deploying a --debug-prerender build. It disables minification.
  • Scripting next lint. The command was removed in 16.0.
  • Setting PORT in .env. The server binds before .env is read.
