next.config reference

The next.config options that matter in Next.js 16.3, with types, defaults and whether each is current, opt-in, experimental or deprecated.

NNext.jsCurrentNext.js 16.3+Targets Next.js 16.3

Types and defaults below were read from the NextConfig type and the default config shipped in next@16.3.5, and cross-checked against the bundled docs. This is not every option. It is the set you are likely to set, plus the ones people still set from memory and should not.

Labels. Current: stable, top-level. Opt-in: stable behavior behind a flag you set on purpose. Experimental: the key lives under experimental and may change. Several stable behaviors are tuned through an experimental.* key; there the label describes the key, not the behavior. Deprecated: still read, do not use.

The config file#

next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  cacheComponents: true,
  reactCompiler: true,
  typedRoutes: true,
  images: {
    remotePatterns: [{ protocol: 'https', hostname: 'images.example.com' }],
  },
  cacheLife: {
    editorial: { stale: 300, revalidate: 900, expire: 86400 },
  },
  async redirects() {
    return [{ source: '/docs/old', destination: '/docs', permanent: true }];
  },
};

export default nextConfig;

next.config.ts, next.config.js and next.config.mjs are supported; .cjs and .cts are not. The default export may also be a function (phase, { defaultConfig }) => config, sync or async. In 16.0 the config loads once in next dev, so process.argv.includes('dev') is false there; use phase or process.env.NODE_ENV.

Common mistakes#

  • Setting partialPrefetching without cacheComponents. The config fails validation.
  • Putting partialPrefetching or typedRoutes under experimental. Both are top-level.
  • Putting serverActions.bodySizeLimit at the top level. In 16.3.5 it lives under experimental.serverActions.
  • Reading an experimental.* key as "this feature is experimental". The Turbopack filesystem caches and prefetch inlining are on by default; only their tuning keys are experimental.
  • Leaving a plugin's webpack hook in place and wondering why next build fails. Turbopack is the default; pass --webpack or migrate the hook.
  • Using images.domains. It is deprecated and cannot restrict protocol or path. Use remotePatterns.
  • Checking process.argv for dev in the config. Since 16.0 it is false under next dev.
