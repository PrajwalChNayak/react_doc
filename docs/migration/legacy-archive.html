Legacy archive

Every page of the previous documentation, preserved under a banner, mapped to what replaced it.

Legacy

This site replaces an earlier hand-built React documentation site. That site was written before React 19 and teaches APIs that no longer exist.

Nothing was deleted. Every page of it is preserved byte-for-byte under legacy/pages/, with one addition: a banner injected at the top of each page saying it is archived, and linking to the page that replaced it.

Legacy

Everything linked from this page is pre-React-19 material. Several pages teach APIs removed in 19.0 — ReactDOM.render, propTypes, defaultProps, <Context.Provider>. Read them to understand code you have inherited, never to decide how to write something new.

The archive policy#

Three rules, applied to every file:

  1. Nothing is deleted. Old documentation is the only surviving explanation of why some code in your repository looks the way it does. Deleting it makes that code unreadable.
  2. Nothing is edited. The pages are unchanged apart from the banner. If a page was wrong, the banner says so and the replacement page fixes it — the archived text keeps saying what it always said.
  3. Every page has a named replacement. No archived page is a dead end. The banner links forward, and so does the table below.

The banner is self-contained inline HTML because these pages loaded Tailwind from a CDN. When that CDN eventually stops serving the version they ask for, the pages will lose their styling and the banner will still be legible.

legacy/ sits beside docs/ at the repository root, so the banners link across with ../../docs/... from a page and ../../../docs/... from a redux/ fragment.

The assets/ directory is part of the archive too. The old site had no build step: components-loader.js fetched the shared header and footer into every page at runtime, and redux-loader.js fetched the five Redux fragments into redux.html. That is why those five files have no <html> or <body> of their own, and why opening one directly shows a section rather than a page.

What the banner says#

Every archived HTML page opens with the same block:

ARCHIVED — pre-React-19 documentation
This page is kept for reference only and contains APIs that were removed or
deprecated in React 19. Current replacement: <page>. See the archive index.

The five redux/ files are HTML fragments rather than whole documents — the old site loaded them into redux.html with a script — so their banner sits at the top of the fragment instead of after a <body> tag. Opened directly, they still show it.

What was worth keeping#

Archiving is not the same as dismissing. Several things in these pages were better than what usually gets written, and have been carried forward rather than rewritten from scratch:

  • The RTK Query page's request lifecycle walkthrough, which is more concrete than most library documentation on the subject.
  • The Router v5-to-v6 migration table, as a model: a two-column before/after table is the right shape for a migration page, and Removed APIs uses it.
  • The api-integration polling and cancellation examples, which correctly aborted in-flight requests — a detail most tutorials skip.
  • The performance page's Web Vitals section, still the right set of numbers to watch.

What did not survive was the structure. The old site had one enormous page per topic — 145 KB for components — with no way to link to a specific idea. One concept per file, which this site enforces, is the main structural difference.

Common mistakes#

Copying code out of an archived page into a React 19 app. Roughly half of these pages contain at least one removed API. The banner is at the top of every one of them for this reason.

Assuming an archived page is wrong. Most of them were correct when written. redux-toolkit.html and rtk-query.html are still substantially accurate. Archived means superseded, not false.

Deleting the archive during a cleanup. These pages are the record of why existing code looks the way it does. They cost a few hundred kilobytes.

Editing an archived page to fix it. Then it is neither an accurate record nor current documentation. Fix the replacement page; the archive stays frozen.

Searching only the new site. If you cannot find how something used to be done, the archive is where it is. Search legacy/pages/ before concluding it was never documented.

Trusting the framework and library versions in these pages. Router, Formik, Yup, axios and redux-persist have all moved on. Check the current documentation for anything outside React itself.
