## Overview

In a React SPA, folder names are a team convention. In Next.js, **some file and
folder names are API**: `app/blog/[slug]/page.tsx` defines a URL, `proxy.ts`
at the root runs before every matched request, and `_components/` opts a folder
out of routing. Everything else is yours to organize.

This page maps the project. The routing pages explain each convention in depth.

## Why it exists

File-system routing removes a route table you would otherwise maintain by hand,
and it lets Next.js know, at build time, which code belongs to which route. That
is what makes per-route code splitting, prerendering and generated route types
possible. The cost is that a misplaced or misnamed file silently changes
behavior, so the names are worth learning once.

## When to use it

Read this page when you open a Next.js project for the first time, when you
decide where shared code should live, or when a file you created is not being
picked up.

## When not to use it

The full list of file conventions, with every export each one accepts, lives in
[File conventions](../nextjs-routing/file-conventions.md). Come back here for
the overview.

## Basic example

A typical project created by `create-next-app` and extended with a few routes:

```text
my-app/
├── app/                      # App Router: routes, layouts, boundaries
│   ├── layout.tsx            # root layout (required)
│   ├── page.tsx              # "/"
│   ├── globals.css
│   ├── blog/
│   │   ├── page.tsx          # "/blog"
│   │   ├── [slug]/
│   │   │   └── page.tsx      # "/blog/:slug"
│   │   └── _components/      # private folder: never routable
│   │       └── post-card.tsx
│   └── api/
│       └── health/
│           └── route.ts      # GET /api/health
├── lib/                      # your code: data access, utilities
├── public/                   # static files served from "/"
├── proxy.ts                  # optional: runs before matched requests
├── instrumentation.ts        # optional: runs once when the server starts
├── next.config.ts
├── tsconfig.json
├── package.json
├── eslint.config.mjs
├── AGENTS.md                 # instructions for AI coding agents
├── next-env.d.ts             # generated, gitignored
└── .next/                    # build and dev output, gitignored
```

## How it works

### Top-level files

| File | Purpose |
|---|---|
| `next.config.ts` | Framework configuration. TypeScript is supported and typed with `NextConfig`. See [TypeScript](./typescript.md). |
| `package.json` | Dependencies and the `dev` / `build` / `start` scripts. |
| `tsconfig.json` | TypeScript options, the `next` plugin, and the `@/*` alias. |
| `next-env.d.ts` | Generated by `next dev`, `next build` and `next typegen`. Do not edit or commit it. |
| `proxy.ts` | Request interception: redirects, rewrites, headers. Exports a `proxy` function (named or default) and an optional `config.matcher`. Runs on the Node.js runtime. |
| `instrumentation.ts` | Exports `register()`, called once when a server instance starts, and optionally `onRequestError`. Used for OpenTelemetry and error reporting. |
| `instrumentation-client.ts` | Client-side instrumentation that runs before the app becomes interactive. |
| `.env`, `.env.local`, `.env.development`, `.env.production` | Environment variables. Keep secrets out of version control. See [Environment variables](../nextjs-backend/environment-variables.md). |
| `eslint.config.mjs` | ESLint flat config, if you chose ESLint. |
| `AGENTS.md`, `CLAUDE.md` | Written by `create-next-app` and by `next dev`. See [AI coding agents](./ai-agents.md). |

> [!NOTE]
> `proxy.ts` replaced `middleware.ts` in Next.js 16.0. The old file name is
> deprecated. See [Middleware to proxy](../nextjs-migration/middleware-to-proxy.md)
> if your project still has one.

### Top-level folders

| Folder | Purpose |
|---|---|
| `app/` | The App Router. Every route, layout and boundary lives here. |
| `public/` | Static files served as-is from the site root: `public/logo.svg` is `/logo.svg`. |
| `src/` | Optional. Holds `app/` and your other application code, to separate it from config files. |
| `.next/` | Output. `next build` writes to `.next`, `next dev` writes to `.next/dev`. Never commit it. |

`pages/` is the legacy Pages Router directory. This site does not document it.

### `app/` conventions at a glance

| File | Role | Details |
|---|---|---|
| `layout.tsx` | UI shared by a segment and its children. State is preserved across navigation. | [Pages and layouts](../nextjs-routing/pages-and-layouts.md) |
| `page.tsx` | Makes a segment publicly routable. | [Pages and layouts](../nextjs-routing/pages-and-layouts.md) |
| `loading.tsx` | Suspense fallback for the segment. | [Loading UI](../nextjs-errors/loading-ui.md) |
| `error.tsx`, `global-error.tsx` | Error boundary for the segment, or for the root layout. | [Error boundaries](../nextjs-errors/error-boundaries.md) |
| `not-found.tsx` | UI for `notFound()`. | [Not found and redirect](../nextjs-errors/not-found-and-redirect.md) |
| `route.ts` | An HTTP endpoint instead of a page. | [Route Handlers](../nextjs-backend/route-handlers.md) |
| `template.tsx` | A layout that remounts on every navigation. | [File conventions](../nextjs-routing/file-conventions.md) |
| `default.tsx` | Fallback for a parallel route slot. Required for every slot. | [Parallel routes](../nextjs-routing/parallel-routes.md) |

Folder names carry meaning too:

| Folder name | Effect | Details |
|---|---|---|
| `blog` | A URL segment. | [Pages and layouts](../nextjs-routing/pages-and-layouts.md) |
| `[slug]`, `[...slug]`, `[[...slug]]` | Dynamic, catch-all and optional catch-all segments. | [Dynamic segments](../nextjs-routing/dynamic-segments.md) |
| `(marketing)` | Route group: organizes files and layouts without adding a URL segment. | [Route groups](../nextjs-routing/route-groups.md) |
| `_components` | Private folder: it and all its subfolders are excluded from routing. | This page |
| `@sidebar` | Named slot for a parallel route. | [Parallel routes](../nextjs-routing/parallel-routes.md) |
| `(.)photo`, `(..)photo` | Intercepting route. | [Intercepting routes](../nextjs-routing/intercepting-routes.md) |

Metadata files such as `favicon.ico`, `icon.tsx`, `opengraph-image.tsx`,
`sitemap.ts` and `robots.ts` also live in `app/`. See
[Metadata](../nextjs-styling/metadata.md).

## Common patterns

### Colocate route-specific code

A folder in `app/` is not routable until it contains `page.tsx` or `route.ts`,
and even then only what those two files return is sent to the client. So a
component or helper next to a page is safe:

```tsx file="app/blog/_components/post-card.tsx"
import Link from 'next/link';

type PostCardProps = {
  slug: string;
  title: string;
  excerpt: string;
};

export function PostCard({ slug, title, excerpt }: PostCardProps) {
  return (
    <article>
      <h2>
        <Link href={`/blog/${slug}`}>{title}</Link>
      </h2>
      <p>{excerpt}</p>
    </article>
  );
}
```

```tsx file="app/blog/page.tsx"
import { PostCard } from './_components/post-card';
import { getPosts } from '@/lib/posts';

export default async function BlogPage() {
  const posts = await getPosts();

  return (
    <main>
      <h1>Blog</h1>
      {posts.map((post) => (
        <PostCard key={post.slug} slug={post.slug} title={post.title} excerpt={post.excerpt} />
      ))}
    </main>
  );
}
```

The underscore is not required for safety. Use private folders anyway, because
they make intent visible, sort together in editors, and cannot collide with a
file convention Next.js adds in a future release.

### Keep shared code outside `app/`

Code used by many routes (data access, auth helpers, design-system components)
usually reads better in root folders such as `lib/` and `components/`, imported
through the `@/*` alias. Next.js gives these names no special meaning. Pick one
strategy and apply it consistently.

### Use a `src/` folder

Move `app/` to `src/app/` to separate application code from configuration.
When you do:

- `proxy.ts` and `instrumentation.ts` move into `src/` too, at the same level as
  `app/`.
- `public/`, `package.json`, `next.config.ts`, `tsconfig.json` and `.env*` files
  stay at the project root.
- Update the `@/*` path in `tsconfig.json` to `./src/*`.
- If both `app/` and `src/app/` exist, `src/app/` is ignored.

### Put `proxy.ts` next to `app/`

```ts file="proxy.ts"
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function proxy(request: NextRequest) {
  return NextResponse.redirect(new URL('/blog', request.url));
}

export const config = {
  matcher: '/articles/:path*',
};
```

It must sit at the project root, or in `src/` when you use one, at the same
level as `app/`. That is the only place Next.js looks for it. Proxy is for redirects, rewrites and headers.
It is not an authorization layer. See [Proxy](../nextjs-backend/proxy.md).

## Common mistakes

- **Creating a folder and expecting a route.** Without `page.tsx` (or
  `route.ts`) the segment returns 404.
- **Putting `page.tsx` and `route.ts` in the same segment.** Next.js does not allow
  a `route.ts` at the same route as a `page.tsx`. Move the endpoint under
  `app/api/` or another segment.
- **Placing `proxy.ts` inside `app/`.** It belongs at the root or in `src/`.
- **Keeping `middleware.ts` in a Next.js 16 project** as if it were current. It
  is deprecated. Rename it to `proxy.ts` using the migration page.
- **Having both `app/` and `src/app/`.** Next.js ignores `src/app/` when a root
  `app/` exists, so the routes you edit under `src/` never appear.
- **Treating `public/` files as private.** Everything in `public/` is served to
  anyone who guesses the path.
- **Committing `.next/` or `next-env.d.ts`.** Both are generated.
